# Pinned environment for cluster runs. Install into a fresh venv, then record it:
#
#     python -m pip install -r indic/requirements-hpc.txt
#     python -m indic.hpc.capability          # every card must say "in build: yes"
#     python -m indic.hpc.env_lock capture --out runs/<sweep>/env.lock.json
#
# Why pins at all: arms of this experiment are produced weeks apart on different
# nodes. transformers changing an attention default, or numpy changing a rounding
# rule, moves CER by a fraction of a point for reasons that have nothing to do
# with the tokenizer under test. These versions are the ones the work was done
# against; `indic/hpc/env_lock.py` is what notices when a node disagrees.
#
# Verified on CPython 3.12. On an older interpreter pip will refuse a pin rather
# than quietly resolving something else, which is the intended failure.

# ─── torch: pin the VERSION, choose the BUILD per cluster ─────────────────────
# There is no torch wheel that is right everywhere, so this file does not pretend
# there is. A wheel carries compiled kernels for a fixed set of architectures, and
# a card outside that set fails at the first kernel launch with "no kernel image
# is available for execution on the device" — not at install time, not at import,
# but twenty minutes into the job.
#
# The wheel this work was developed against (torch 2.11.0+cu128 on a laptop
# Blackwell card) carries sm_75 and newer. On an A100/H100 cluster that is fine.
# On anything with V100s it is not, and installing it there wastes an allocation.
#
# To choose:
#
#   1. On a login node of the target cluster, find out what the cards are:
#          nvidia-smi --query-gpu=name,compute_cap --format=csv
#      or, once torch is installed, just run `python -m indic.hpc.capability` —
#      its "in build" column compares each card against the wheel's arch list and
#      says NO when they do not match.
#
#   2. Install the matching build by index, not by hoping PyPI's default fits:
#          pip install torch==2.11.0 torchaudio==2.11.0 \
#              --index-url https://download.pytorch.org/whl/cu121
#      Substitute the CUDA tag the cluster's driver supports (cu118, cu121, cu124,
#      cu126, cu128, ...). The driver has to be at least the minimum for that
#      runtime major — capability.py checks this too and names the number.
#
#   3. If no build of this torch version still ships kernels for the cluster's
#      oldest cards, drop to an older torch that does, and say so in the lock
#      file: a sweep that mixes torch versions across arms is two experiments.
#
# Pinned without a local `+cuXXX` suffix on purpose, so step 2's --index-url
# decides the build and this line only decides the version.
torch==2.11.0
torchaudio==2.11.0

# NOT PINNED, deliberately: nvidia-cublas-cu12, nvidia-cudnn-cu12, nvidia-nccl-cu12
# and the rest of the nvidia-* wheels. They arrive as dependencies of whichever
# torch build is installed, and pinning them here would silently force the cu128
# stack back onto a cluster that asked for cu121.

# ─── intentionally absent ─────────────────────────────────────────────────────
# flash-attn: not installable from a plain wheel on most clusters (it compiles
#   against the local CUDA toolkit and takes tens of minutes), and sm_80+ only.
#   `indic.hpc.capability.select_attn_implementation` falls back to SDPA without
#   it, which costs some speed and changes nothing numerically. Install it
#   separately per cluster if the sweep is long enough to pay back the build.
# vllm: an optional acceleration path (see docs/vllm.md) with its own very
#   specific torch pin. Mixing it into this file would make the base install
#   depend on whether the cluster can run vLLM at all.
# espeakng_loader / phonemizer / onnxruntime: only the legacy ONNX models need
#   them, and espeak is a system library a compute node may not have.
